    【08】AI 時代的工作方式：先與 AI 協作，再開始開發

    [ 08 ] AI-Native 工作方法 ⏱️ 閱讀時間 8 分鐘 ✍️ 作者：Falo x Force Cheng (2026/7/28)

    這不是 AI Coding，而是真正的 AI-Native 工作方法

    AI 時代最大的改變，不是 AI 幫我們寫程式。而是：AI 可以成為專案的第一位顧問與架構師！
    過去從客戶需求到開始開發，需要大量的會議與文件整理；現在，這些前置作業都可以先交給 AI 高效完成！

    一、本章核心觀念：AI 是專案的第一位顧問

    過去在軟體開發或 ERP 整合中，最大的浪費通常發生在「需求理解錯誤」與「寫完程式才發現客戶要的不一樣」。

    💡 重新定義 AI 的角色

    AI 不只是程式設計工具，更是需求分析、方案設計與 PoC 驗證的重要助手！
    不要急著讓 AI 產出 Python 代碼。先讓 AI 幫助我們分析業務邏輯、劃分邊界、繪製 UI 與 Workflow 示意圖，確認規格後才進入寫碼階段。

    二、傳統開發流程 vs. AI Native 工作流程對比

    比較兩種模式的差異，你會發現 AI Native 大幅縮短了資訊模糊期，降低了溝通摩擦：

    傳統開發流程 (Traditional)

    文字 ➔ 會議 ➔ 猜測 ➔ 寫碼

    客戶需求
      │
      ▼
    需求訪談 (來回多次會議)
      │
      ▼
    規格整理 (文字文件堆疊)
      │
      ▼
    開始寫程式 (高修改風險 ⚠️)

    ⚠️ 傳統痛點：通常需要經過多次來回討論與修改，開發完成後才發現與客戶腦中想的完全不同。

    AI Native 工作流程 ⭐ 推薦

    需求 ➔ AI 協作分析 ➔ Prototype/PoC ➔ 確認 ➔ AI Coding

    客戶需求
      │
      ▼
    全部交給 AI 協助分析與產出：
      ├── 整理需求 & 補充功能建議
      ├── 畫 UI 示意圖 & 系統架構圖
      ├── 畫 Workflow & 建立資料流程
      ├── 撰寫 Spec & 評估技術方案
      └── 製作 HTML Demo & MVP / PoC
      │
      ▼
    與客戶討論 ➔ 確認需求 ➔ AI Coding

    🚀 核心優勢：AI 不只是程式設計師，更像是一位全天候的產品顧問與架構師。

    三、AI 可以協助哪些資料分析？（多元素材輸入）

    在正式開始開發之前，可以把專案相關的各種非結構化與多模態資料直接丟給 AI：

    📹 會議與 ERP 操作螢幕錄影檔
    🎙️ 全程訪談錄音與逐字稿
    🖍️ 白板討論照片 & 手寫草稿
    📄 劃線塗改紙本單據拍照
    🏭 產線設備與銘牌標籤照片
    📝 客戶口述與需求說明文字
    📄 PDF 業務文件與 Word 草案
    📊 Excel 報表與歷史表格
    🖼️ 舊天心 ERP 操作畫面截圖
    🔀 跨部門業務流程圖
    🔌 API 接口說明書與 Schema
    ✉️ 客戶往來 Email 與會議紀錄

    💡 AI 能夠在數秒內跨格式讀取重點、釐清邏輯矛盾，並主動提出改善建議。

    📸 多模態非結構化輸入：從錄影/錄音/手寫/白板照片到 AI 轉譯交棒

    真實專案中，客戶常無法整理規格。多模態 AI 能直接消化各種現場非結構化資料，自動轉譯為數位規格：

    📹 螢幕操作錄影檔
    客戶示範舊 ERP 流程的螢幕側錄，Gemini 1.5 Pro 可直接讀取影片，提取精確點擊步驟與痛點。
    🖍️ 白板與手寫草圖
    開會隨手畫在白板上的系統架構與流程圖照片，AI 自動識別箭頭意圖並轉化為 Mermaid 視覺圖。
    📄 劃線塗改實體單據
    客戶用紅筆批註修改特例的銷貨單/發票照片，AI 自動比對原表格並抓出需擴充的欄位與邏輯。
    🎙️ 訪談錄音與逐字稿
    NotebookLM 數秒內 digest 多小時訪談音訊，提煉精確 FAQ 並交棒 AI Agent 自動生成 Prototype。
    ⚡ 實務省費技巧：Google Gemini 影片 Token 暴降 80%~90% 的原生 API 參數與處理手法

    在呼叫 Google Gemini (Gemini 1.5 Pro / 2.0 Flash) 多模態 API 處理長影片時，預設會以 1 FPS（約每秒 263 Tokens）抽樣。透過以下原生參數與預處理，可將 Token 消耗直降 90%：

    1. ffmpeg 關鍵定格抽樣 (fps=0.2 ~ 0.5)
    透過 ffmpeg 將 10 分鐘影片預先萃取為 2~5 秒一張定格圖或降為 0.2 FPS（每 5 秒 1 幀），Token 直接節省 80%！
    2. Gemini File API 寬高重定 (720p Scaling)
    將 4K 錄影畫面縮放至 1280x720 (720p)，每幀圖檔 Token 鎖定在最平價區間，畫面細節依然清晰可辨。
    3. 時間戳記導引 (Timestamp Range Prompt)
    在 Prompt 中加入 `[01:15-02:30]` 時間區段限制，Gemini 會精準焦距目標片段，省去無效畫面的處理成本。
    # 💡 1. 預處理：使用 ffmpeg 抽樣降低影格與解析度 (縮降 90% Token)
    ffmpeg -i erp_demo.mp4 -vf "fps=0.2,scale=1280:-1" -q:v 2 frames_%03d.jpg

    # 💡 2. Google Gemini API 呼叫範例 (Python google-genai SDK)
    import google.generativeai as genai
    video_file = genai.upload_file("frames_preview.mp4", mime_type="video/mp4")
    model = genai.GenerativeModel("gemini-1.5-pro")
    response = model.generate_content([
        video_file,
        "分析 [00:30-02:00] 操作步驟，以 JSON 格式輸出：1. UI 欄位變更 2. 按鈕點擊動作 3. 天心 ERP 拋轉 API Payload"
    ])

    四、AI 可以先產出哪些實質成果？（寫 Code 之前）

    在真正撰寫任何 Python 後端代碼前，AI 可以幫助我們預先產出以下豐富的專案資產：

    • 📋 功能需求分析 (Requirements Breakdown)：自動拆解主功能、次功能與邊界例外狀況。
    • 🗺️ 系統架構圖 (System Architecture)：清晰規劃前端、AI Engine、FastAPI 服務與地端 ERP 的對接關係。
    • 🔀 資料流程圖 (Data Workflow)：明確定義 API Payload 格式與資料傳遞方向。
    • 📐 UI Wireframe & HTML Prototype (FALO 第一原則)：直接產出可點擊互動的 HTML 網頁原型，讓客戶第一秒就能看見成果！
    • 🚀 POC (Proof of Concept) & MVP (Minimum Viable Product)：小規模驗證可行性。
    • 🔌 API 規格書 & Database Schema：自動生成 JSON Schema 與 SQLite/PostgreSQL 資料庫表格結構。
    • 🧪 測試案例 (Test Cases) & 專案時程建議：提前規劃邊界測試與預估工時。

    🛠️ AI Native 推薦實戰工具箱 (Recommended AI Toolset)

    工欲善其事，必先利其器！在「需求分析 ➔ 示意圖 ➔ PoC 驗證」的不同階段，選對適合的 AI 工具能讓效率倍增：

    🎨

    需求整理、畫圖與架構視覺化

    適合用於分析非結構化文件、整理業務重點、畫出系統架構圖與 UI 原型示意圖：

    • ChatGPT Plus (或更高版本)：具備強大 DALL-E 3 圖像生成、Canvas 互動畫布、GPT-4o 視覺分析與強大的 Markdown / Mermaid 圖表繪製能力，是需求整理與架構畫圖的首選！
    • NotebookLM (Google 知識庫助手)：極度推薦在客戶同意下，搭配全程訪談錄音檔直接餵給 NotebookLM 解析成逐字稿與結構化重點摘要，無痛提煉多小時會議精髓！
    🚀

    PoC 驗證與 Prototype 原型構建

    適合用於 10 分鐘內建立可執行的 PoC 驗證檔、發票多模態測試與全方位素材解析：

    • Google Gemini Canvas (純瀏覽器免安裝 ➔ 客戶電腦即開啟 PoC 神器)：專心聚焦做 PoC 原型展示！只要有網路與瀏覽器，直接在客戶公司的電腦或簡報筆電上開啟即可使用。特別適用於「不須」或「受限於企業資安條款而不能安裝外來 AI Agent / IDE 開發環境」的現場場域，依然能在 10 分鐘內即時構建 HTML/JS 互動 Prototype 展示觀念驗證成果！
    • Google Antigravity (Agentic AI Engine)：用於全方位解析與消化所有輸入來源（包含螢幕側錄影片、訪談錄音逐字稿、手寫草稿、白板照片、劃線紙本單據、PDF 規格書與 ERP 畫面），並在 10 分鐘內自動產出完整的 HTML First 前端原型與 Python 後端 API 代碼，極速驗證技術可行性！

    🎙️ 顧問實務神技：歷史談話紀錄 (錄音+逐字稿) ➔ NotebookLM 摘要 ➔ 交棒 AI Agent

    超越人類的高效理解流程：在取得客戶同意的前提下，將跨數週的歷史需求訪談錄音檔與逐字稿直接丟給 NotebookLM。它不僅能完整歸納談話紀錄，更能讓 AI 在數秒內迅速理解龐大複雜的業務全貌（效率遠超越人類人工整理）；接著將此精練摘要正式「交棒」給 AI Agent（如 Google Antigravity / Gemini），在 10 分鐘內自動產出 HTML 互動原型與 PoC API，打造令人讚嘆的顧問體驗！

    💡 高階繪圖密技：Agent 產出 SVG 初步向量圖 ➔ ChatGPT 接棒美化

    絕妙的多 AI 協作技巧：先請 AI Agent（如 Antigravity）根據需求快速生成結構精確的原始 SVG 向量圖或 Wireframe 代碼；接著將此 SVG 向量圖檔或代碼直接提供給 ChatGPT Plus (Canvas / DALL-E 3)，讓 ChatGPT「接棒」進行視覺配色、燈光質感與風格美化，瞬間產出頂級企業大廠水準的 UI 設計圖與系統架構圖！

    五、實務案例：發票辨識與 ERP 匯入系統

    假設客戶提出這樣一個經典需求：

    💬 客戶需求說明：

    「我們需要一套可以自動辨識電子發票/紙本發票，並將金額與統編自動匯入天心 ERP 的系統。」

    ❌ 錯誤的傳統反應（急著寫 Code）：

    馬上打開 VS Code 寫 Python `pip install pytesseract opencv`，花了三天寫完，結果客戶說：「我們要的是網頁介面，而且發票有很多種格式要預覽對照，不是跑背景腳本！」➔ **白忙一場！**

    ✅ 正確的 AI Native 協作步驟：

    1. 分析需求 ➔ 把發票範本丟給 AI，分析必須辨識的欄位（發票號碼、日期、未稅額、稅額、總金額、賣方統編）。
    2. 提出功能建議 ➔ AI 建議加上「辨識結果人工覆核比對 UI」與「異常金額警示」。
    3. 畫出操作流程 ➔ 生成 使用者上傳 ➔ AI 辨識 ➔ 畫面比對 ➔ 確認拋轉 ERP 的 Workflow。
    4. 畫出系統架構 ➔ 定義 HTML 前端 + Python FastAPI Engine + Cloudflare Tunnel 穿透。
    5. 製作 HTML 示意畫面 (Prototype) ➔ 10 分鐘內產出 HTML 網頁原型！
    6. 建立簡單 PoC 驗證 ➔ 拿 3 張實際發票丟給 Gemini API 測試準確率。
    7. 與客戶開會確認 ➔ 拿著 HTML Prototype 與客戶對齊：「這就是您要的介面與流程嗎？」
    8. 開始 AI Coding ➔ 規格 100% 確認後，再請 AI 生成正式生產代碼！

    六、AI Native 的 5 大核心思維

    真正的 AI-Native 專業人員，重視的是「溝通成本」與「驗證速度」：

    1. 協助理解需求
    從隱晦模糊的客戶口述中，自動提煉出明確的系統功能點。
    2. 提供多元解決方案
    同時評估專用 OCR、LLM 多模態與 Cloud Run / Tunnel 等不同架構優缺點。
    3. 快速建立 Prototype
    貫徹 FALO 第一原則（HTML First），第一時間做出有溫度的互動原型。
    4. 大幅降低溝通成本
    用可視覺化的 HTML 介面與 Workflow 圖取代幾十頁枯燥的文字規格書。
    5. 提前驗證可行性
    許多潛在盲點與邏輯衝突，在正式開發前就已經被發現並修正完畢。

    🏆 本章核心金句

    「不要急著讓 AI 寫程式。
    先讓 AI 幫你理解需求、整理想法、畫出示意圖、完成 PoC，再開始開發。」

    真正的 AI-Native 開發流程，不是「需求 ➔ 程式」，而是：

    需求 ➔ AI 協作 ➔ Prototype／PoC ➔ 規格確認 ➔ AI Coding ➔ 正式系統
