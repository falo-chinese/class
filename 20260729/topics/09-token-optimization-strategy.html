【09】台灣企業實務落地模式：先不計 Token 達成目的 ➔ 再逐步互動優化降 Token

打破「過度早優化 (Premature Optimization)」的迷思！專案初期不計成本驗證商業價值與 PoC 成功，中期透過 AI 互動與技術參數將 API 費用暴降 80%~90%！

一、台灣企業 AI 專區實務痛點

在台灣中小企業與銀河軟體 專案落地的第一線，許多工程團隊常陷入一個致命的開發誤區：

⚠️ 傳統過度早優化 (Premature Optimization) 的陷阱：

「專案還沒開始，工程師就花好幾天絞盡腦汁寫精簡 Prompt、縮減 Token 上下文，甚至把高解析度發票圖檔壓縮成模糊小圖... 結果第一天 Demo 辨識率大失常，主管與客戶直接信心崩盤，專案胎死腹中！」

💡 台灣企業文化洞察：「省費導向」下，必須將「開發階段」與「營運階段」完全拆開！

台灣企業普遍具備極高的成本敏感度（Cost-conscious）。但必須釐清：「開發/驗證階段」與「正式營運階段」是兩個完全不同的維度與概念！

🛠️ 開發與驗證階段 (Development Phase)
追求速度、驗證與商業價值！ 這時省幾塊錢的 Token 費用是「省小錢、賠大錢」。應該花小小的 API 費用，極速換取 100% 驗證成功與客戶點頭認可！
🚀 正式營運階段 (Operations Phase)
追求高效率、極致省費與穩定輸出！ 規格與邏輯確定後，這時候才進行切換純程式碼、0.2 FPS 抽樣與 Context Caching，讓每日百萬次呼叫的成本降至最低！

二、核心戰略：兩階段進化法 (Make it Work ➔ Make it Cheap)

最適合台灣企業專案落地的 AI 核心原則是：「 Make it Work, Make it Fast, Make it Cheap 」（先讓它運作 ➔ 讓它快速 ➔ 讓它便宜）。

🎯

第一階段：先不計 Token 達成目的

功能與商業驗證第一！ 大膽提供給 AI 最高畫質素材、全量Context 與詳細需求，100% 跑通 PoC 與 HTML 可互動原型。

💡 核心目標：拿到主管與客戶的簽核點頭，確保商業價值存在！
⚡

第二階段：逐步互動精簡 Token 費用

運營成本最佳化！ 當需求與規格完全鎖定後，再透過 AI 互動寫出可重複利用的 JSON 模板與抽樣參數，費用直降 90%！

💡 核心目標：準備上線正式環境，讓 API 營運成本趨近於零！

三、第一階段：與 AI 溝通「先達成目的，不用特別考慮成本」(Make it Work)

在需求討論與 PoC 驗證初期，跟 AI 溝通時最重要的一句話就是：「請盡量完成我的目標，先不用特別考慮 Token 成本！」

  • 🖼️ 全量高畫質素材輸入：提供最完整的上下文、4K 發票照片、白板草圖與長錄音檔，不刻意壓縮圖片，確保 AI 擁有一流的資訊視覺與 100% 辨識準確率。
  • 💡 讓 AI 大膽推理與提案：請 AI 協助整理需求、規劃架構、建議例外處理狀況，並在 10 分鐘內產出 HTML 可互動 Prototype！
  • 🎯 鎖定核心價值：以「能讓客戶與主管看見、點擊並驗證成功」為唯一 KPI，第一時間取得認可！

💡 Force 老師靈魂提醒：補充領域經驗給 AI，但千萬不要侷限它！

「在與 AI 溝通時，我們可以大膽提供領域經驗與業務 Context 補充給 AI，但千萬不要過度約束或劃地自限！因為 AI 通常比我們更博學（具備全球跨領域知識庫），而且它的創意與聯想力一點也不輸人類！給予 AI 開放式的揮灑空間，它往往能帶給你意想不到的驚豔方案！」

🔄 關鍵過渡橋樑：如何從「完成 PoC」流暢邁向「降本優化設計」？

當 AI Agent 幫你完成了令人讚嘆的 PoC 成果後，千萬不要急著直接寫 Code！請遵循以下 3 步落地橋樑：

1. 向 AI Agent 請教詳細步驟
請 AI 說清楚講明白：「請列出你完成這個任務時，所使用的每一個思考步驟、Prompt 邏輯、API 呼叫順序與資料解析邏輯！」讓 AI 交付完整細節。
2. 與使用者/主管充分討論對齊
拿著 AI 的步驟拆解與 HTML 互動原型，與客戶徹底檢視：「哪些步驟是必須的？哪些例外狀況要補強？哪個 UI 畫面才是最終要的？」對齊真正規格！
3. 再來進行最終優化設計
規格 100% 確定後，才進行「切換非 Agent 純 Code」與「少用 LLM 精簡 Token」的最終工程重構，打造營運成本最低、防護力最強的正式系統！

四、第二階段：與 AI 互動優化——降 Token、切換非 Agent 程式與穩定輸出

當 PoC 驗證成功並確定規格後，接著與 AI 互動進行「雙重降本增效與防護優化」：

⚡

優化方向 1：切換為「不需要 AI Agent」的純程式碼作法

PoC 階段驗證成功後，正式生產環境不要持續跑高成本、動態思考的重型 AI Agent：

  • 純程式碼落地：請 AI 將驗證好的邏輯，直接重構成標準的 Python (FastAPI/Requests) 或 JavaScript 腳本。
  • 固定 API 與 SQL 拋轉：用確定性的程式碼處理資料傳輸與銀河軟體 寫入，擺脫對 Agent 循環叫用的依賴。
🛡️

優化方向 2：各環節「少用 LLM、精簡 Token」與穩定輸出

在正式運作流程中，儘可能減少 LLM 的負擔，兼顧省錢與 100% 穩定輸出：

  • 省錢 (Cost Reduction)：關鍵定格 (0.2 FPS) 替代全程影片；用 Python 正則表達式 (Regex) 處理簡單文字萃取，能用程式做的就不花 LLM Token！
  • 穩定輸出 (Deterministic Output)：嚴格強制 JSON Schema 限制，並對固定 ERP 表格結構開啟 Context Caching，徹底消除幻覺風險！
# 💡 實務範例：非 Agent 純 Python 程式 + JSON Schema 確定性輸出 (零幻覺 + 極低 Token)
import google.generativeai as genai
from pydantic import BaseModel

# 1. 用 Pydantic 定義確定性 Schema，保證輸出絕對穩定
class InvoicePayload(BaseModel):
    invoice_num: str
    total_amount: int
    tax_id: str

# 2. 純程式呼叫 (不透過 Agent 輪詢，僅花費單次少許 Token)
model = genai.GenerativeModel("gemini-1.5-flash")
response = model.generate_content(
    [invoice_img, "請依據圖片填寫發票資訊"],
    generation_config={"response_mime_type": "application/json", "response_schema": InvoicePayload}
)
